# Resolvix Frontend

React 19 customer chat and administration dashboard for Resolvix, built with
Vite, Tailwind CSS, React Router, and Axios. The interface signs in against the
FastAPI backend using HttpOnly cookies, restores sessions silently, and manages
the synthetic store and knowledge base through the administrator API.

## Requirements

- Node.js 20 or newer (developed with Node 24)
- The Resolvix backend running at `http://localhost:8000`
- PostgreSQL seeded with the synthetic demo accounts

## Setup

```powershell
cd frontend
npm install
Copy-Item .env.example .env
npm run dev
```

Vite serves the app at http://localhost:5173. The backend must allow that origin
through `CORS_ORIGINS`.

`VITE_API_BASE_URL` configures the API origin. If it is omitted, the app uses
`http://<current-host>:8000`.

## Routes

| Route | Access | Purpose |
|---|---|---|
| `/login` | public | Email/password sign-in |
| `/` | authenticated | Conversation sidebar and chat window |
| `/admin` | admin | Dashboard overview and counts |
| `/admin/faqs` | admin | Create, edit, deactivate, delete, and re-index FAQs |
| `/admin/documents` | admin | Manage and re-index knowledge documents |
| `/admin/orders` | admin | Create orders and manage statuses and line items |
| `/admin/conversations` | admin | Inspect conversations, messages, and metadata |
| `/admin/ai` | admin | Submit test questions and inspect agent responses |

Unauthenticated visitors are redirected to `/login`. A signed-in customer who
opens an `/admin` route is returned to the chat. The backend independently
enforces administrator authorization on every admin route.

## Authentication

- `POST /auth/login` sets HttpOnly access and refresh cookies. The access token
  in the JSON response is **not** written to `localStorage` or any
  JavaScript-readable storage.
- On load, the app calls `POST /auth/refresh` to restore the session from the
  refresh cookie.
- The access cookie is renewed proactively before it expires. If a request
  still receives `401`, the Axios interceptor performs one silent refresh and
  retries the original request.
- Concurrent `401`s share a single refresh request.
- If the refresh session is revoked or expired, the app clears its in-memory
  user, shows a session-expired notice, and redirects to sign-in.
- Logout revokes the refresh token server-side and clears both cookies.

## Chat behavior

- The sidebar loads only the authenticated customer's conversations and
  restores the last selected conversation after a browser refresh.
- **New conversation** creates an empty thread. The first message becomes its
  sidebar title.
- Messages are validated before submission, stored by the backend, and rendered
  from the persisted response rather than an optimistic copy.
- Submissions are blocked while a request is in flight, preventing duplicates.
- Assistant replies are generated by the configured LLM provider and grounded
  in relevant FAQ and policy content retrieved by the backend.
- A fallback reply is shown with a short notice when the provider is
  temporarily unavailable.
- Loading indicators, empty states, and dismissible error notifications cover
  slow, empty, and failed API responses.

## Administration

- **Overview** shows user, order, conversation, and knowledge counts.
- **FAQs** and **Documents** support create, edit, deactivate, delete, and
  re-index. Mutation responses report the indexing outcome; embedding failures
  are shown as errors with the safe reason instead of being treated as success.
- **Orders** supports creating synthetic orders, updating order and shipping
  statuses, and adding, editing, or removing line items. The backend recalculates
  the total after every change.
- **Conversations** lists every conversation with its owner and lets
  administrators inspect persisted user, assistant, and tool messages plus their
  metadata.
- **AI testing** sends questions through the production orchestrator in an
  administrator-owned conversation and displays intent, capabilities, retrieved
  sources, tool calls, latency, and raw metadata.

## Scripts

```powershell
npm run dev      # Vite development server
npm run build    # production build
npm run lint     # ESLint
npm test         # Vitest + Testing Library state tests
```

The tests cover login validation and errors, conversation loading, empty and
failed states, conversation creation, refresh restoration, and duplicate-send
prevention.

## Layout

```
src/
  components/         chat sidebar, message bubbles, icons, route guard
  components/admin/   shared admin UI (tables, banners, modals, fields)
  context/            cookie session restoration and proactive refresh
  layouts/            customer shell and protected admin shell
  pages/              login and chat screens
  pages/admin/        overview, FAQs, documents, orders, conversations, AI test
  services/           Axios client, auth APIs, admin APIs, conversation APIs
  test/               Vitest setup
  utils/              local UI storage, API errors, indexing summaries, dates
```
